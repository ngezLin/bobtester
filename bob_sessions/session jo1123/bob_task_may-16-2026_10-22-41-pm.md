# Scan Engine Migration Guide

This guide explains how to extract the scanning features from this repository and merge them into a separate scan engine repository while preserving git history.

## Overview

The scanning functionality is currently integrated into the main pentest application. This migration will:
1. Extract all scan-related code into a standalone microservice
2. Preserve git history for all moved files
3. Create a clean API boundary between the main app and scan engine
4. Enable independent deployment and scaling of the scan engine

## Migration Steps

### Step 1: Prepare the New Repository

```bash
# Create new repository
mkdir scan-engine
cd scan-engine
git init
```

### Step 2: Extract Files with History (Using git filter-repo)

Install git-filter-repo if not already installed:
```bash
# Windows (using pip)
pip install git-filter-repo

# Or download from: https://github.com/newren/git-filter-repo
```

Extract scan-related files from the main repo:
```bash
# Clone the original repo to a temporary location
cd /tmp
git clone d:/pentest/pentest pentest-temp
cd pentest-temp

# Extract only the files we need with their history
git filter-repo --path workers/ \
                --path types/scan.ts \
                --path lib/logger.ts \
                --path lib/config.ts \
                --path lib/owasp-mapping.ts \
                --force

# Now this repo only contains the scan-related files with full history
```

### Step 3: Merge into New Repository

```bash
# In your new scan-engine repository
cd /path/to/scan-engine

# Add the filtered repo as a remote
git remote add scan-source /tmp/pentest-temp

# Fetch the history
git fetch scan-source

# Merge it into your new repo
git merge scan-source/main --allow-unrelated-histories

# Remove the temporary remote
git remote remove scan-source
```

### Step 4: Restructure Files in New Repo

```bash
# Move files to new structure
mkdir -p src/engine src/queue src/api src/types src/lib src/database

# Move files
git mv workers/scan-engine/* src/engine/
git mv workers/scan-queue.ts src/queue/queue-manager.ts
git mv workers/index.ts src/queue/worker.ts
git mv types/scan.ts src/types/
git mv lib/logger.ts src/lib/
git mv lib/config.ts src/lib/
git mv lib/owasp-mapping.ts src/lib/

# Commit the restructuring
git commit -m "Restructure files for standalone scan engine"
```

### Step 5: Create New Files for Scan Engine

Create these new files in the scan-engine repo:

**src/api/server.ts** - REST API for scan operations
**src/database/client.ts** - Database client for storing findings
**package.json** - Dependencies for scan engine
**tsconfig.json** - TypeScript configuration
**Dockerfile** - Container configuration
**docker-compose.yml** - Local development setup
**.env.example** - Environment variables template

### Step 6: Update Import Paths

Update all imports in the moved files:
```typescript
// Old imports
import { logger } from "@/lib/logger";
import type { ScanFinding } from "@/types/scan";

// New imports
import { logger } from "../lib/logger";
import type { ScanFinding } from "../types/scan";
```

### Step 7: Create API Interface

The scan engine should expose a REST API:

```typescript
// POST /api/scans - Create and queue a new scan
// GET /api/scans/:id - Get scan status
// DELETE /api/scans/:id - Cancel a scan
// GET /api/health - Health check
```

### Step 8: Update Main Application

In the main pentest repo, update `services/scans/scan-service.ts`:

```typescript
// Instead of enqueueScanJob locally
await enqueueScanJob(payload);

// Call the scan engine API
await fetch(`${SCAN_ENGINE_URL}/api/scans`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(payload)
});
```

### Step 9: Remove Old Files from Main Repo

```bash
# In the main pentest repo
cd d:/pentest/pentest

# Remove the scan engine files
git rm -r workers/scan-engine/
git rm workers/scan-queue.ts
git rm workers/index.ts

# Commit the removal
git commit -m "Remove scan engine - moved to separate repository"
```

## Alternative: Using git subtree split (Simpler Method)

If you prefer a simpler approach without external tools:

```bash
# In the main repo
cd d:/pentest/pentest

# Create a new branch with only scan-related files
git subtree split --prefix=workers --branch=scan-engine-export

# In the new scan-engine repo
cd /path/to/scan-engine
git init

# Pull the exported branch
git pull d:/pentest/pentest scan-engine-export

# Clean up the export branch in main repo
cd d:/pentest/pentest
git branch -D scan-engine-export
```

## Deployment Strategy

### Option 1: Docker Compose (Development)
```yaml
version: '3.8'
services:
  scan-engine:
    build: ./scan-engine
    ports:
      - "3001:3001"
    environment:
      - REDIS_URL=redis://redis:6379
    depends_on:
      - redis
  
  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
```

### Option 2: Separate Deployment (Production)
- Deploy scan-engine as a separate service (e.g., on Railway, Render, or AWS)
- Configure main app to point to scan-engine URL
- Use API keys for authentication between services

## Benefits of This Approach

1. **Independent Scaling**: Scale scan workers independently from the main app
2. **Technology Flexibility**: Can rewrite scan engine in different language if needed
3. **Clear Boundaries**: Well-defined API contract between services
4. **Easier Testing**: Test scan engine in isolation
5. **Security**: Isolate potentially risky scanning operations
6. **History Preserved**: All git history for scan files is maintained

## Rollback Plan

If you need to rollback:

1. Keep the old commits in main repo (don't force push)
2. Can cherry-pick commits back if needed
3. Maintain both repos during transition period
4. Use feature flags to switch between local and remote scanning
